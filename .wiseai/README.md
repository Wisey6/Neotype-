# .wiseai

WiseAI job definitions for this project. Everything the agency's hub reads from or writes to this
repo lives under this folder, so nothing here collides with the project's own code.

```
.wiseai/
  jobs/_TEMPLATE.md         the scaffold — copy it, don't edit it
  jobs/<slug>.md            one goal file per job. YOU write these.
  milestones/<slug>.md      optional — the larger goal a set of jobs adds up to
  context/*.md              optional project-specific context for the agent
  status.md                 GENERATED by the hub. Never hand-edit.
  validate.mjs              checks a goal file is well-formed
```

## Creating jobs

In Claude Code, in this repo:

```
/new-job
```

Then either describe one piece of work, or paste the whole pile — meeting notes, a client's wish
list, a punch list. Given a pile it will propose a split first, before writing anything: several
narrow jobs plus a **milestone** they add up to.

That split is not tidiness. The critic scores each job against its `## Outcome` and returns one
number, so a job covering six unrelated things produces a score that cannot say which of the six
is failing — and the loop burns its budget rewriting everything at once. Narrow jobs score
meaningfully; the milestone is what keeps them adding up to the thing the client asked for.

Expect it to tell you what it left out, too. Research ("look into whether Stripe supports this")
and decisions ("pick the pricing tiers") have no finished state a critic could score, so they
come back to you rather than becoming jobs that can never pass.

## The two rules worth knowing

**`status: draft` blocks dispatch.** A goal file sitting in the repo does nothing until you set
`status: ready`. Writing a file is never enough to start spending money. Each job carries its own
budget, so marking six ready at once commits six budgets at once — start a couple and see how the
scores look before releasing the rest.

**Deleting a goal file cancels its job; it does not erase the history.** Runs, costs, and the event
log stay in the hub. If a run is in flight it gets stopped. To remove a job and its history
entirely, delete it from the hub instead — that's a different action because it means a different
thing.

## Checking a file before you commit

```bash
node .wiseai/validate.mjs                     # every job file
node .wiseai/validate.mjs .wiseai/jobs/x.md   # one file
```

The same check runs in the hub before dispatch, so if it passes here it will dispatch there.

## What the critic actually reads

The `## Outcome` section, and nothing else. A vague Outcome produces meaningless scores — the loop
will iterate against a target nobody defined and stop when it plateaus, having spent your budget
learning nothing. Time spent on that section is the highest-leverage thing you can do.
